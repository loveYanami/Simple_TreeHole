# 树洞

一个匿名论坛（树洞）环境：可以注册登录、发帖、评论、点赞，有个人主页。

**它没有后端。** 所有数据由前端的 Mock 层读写，存在你自己浏览器的 localStorage 里。

---

## 先看这里：演示账号

```
用户名：demo
密码：  demo1234
```

登录页已经把它预填好了，直接点「登录」即可。

> 换了浏览器、换了设备、或者开了无痕窗口，都会看到一份全新的初始数据 ——
> 因为数据只存在发起它的那个浏览器里。

| 项 | 要求 |

| 包管理器 | npm（仓库里只有 `package-lock.json`） |

## 快速开始

```bash
npm ci       
npm run dev   # 打开 http://localhost:5173
```

就这么两步。没有数据库、没有后端进程、不需要任何环境变量（`.env.local` 是可选的，
见 `.env.example`）。

## 功能

- **账号**：注册、登录、登出。未登录可以浏览，但发帖、评论、赞踩会跳转登录
- **帖子**：发布、查看详情、删除（仅限自己的）、关键词搜索、「最新 / 热门」排序、分页加载
- **编号**：每条帖子有一个从 1 开始的编号（`#7`），显示在标题旁边，搜索时输入 `7` 或 `#7` 都能找到
- **评论**：发表、删除（仅限自己的）。删除帖子会级联删除其下所有评论
- **赞和踩**：都可以取消，同一个人对同一条帖子只算一次；两者**互斥**，点其中一个会自动撤掉另一个
- **配图**：发帖和评论都可以带图，单次最多 4 张、单张不超过 20 MB，会自动压缩后存储
- **个人主页**：「我的帖子」和「我赞过的」两个标签页

全部数据在刷新后都还在，包括配图。

## 技术选型

Vue 3 + Vite + TypeScript + Pinia + vue-router + Element Plus。

路由用的是 **hash 模式**（URL 里带 `#`）。代价是链接多一个字符，换来的是
`npm run build` 之后的产物在任何静态托管、局域网分享下都零配置可用，
直接刷新任意深链接也不会 404。对一个要交出去、可能被各种方式打开的项目，这个交换划算。

## 匿名是怎么做的

这是整个项目里唯一需要动点脑筋的地方：**树洞要匿名，但个人主页要能列出「我的帖子」**，
这两个诉求表面上是冲突的。

解决办法是把匿名当成**序列化层**的属性，而不是**存储层**的属性：

- 数据里老实保留作者外键（否则「我的帖子」根本无从查起）；
- 但对外传出的数据结构里**根本没有这个字段** —— 取而代之的是一个现算出来的假名。

假名由 `hash(用户id + 帖子id)` 得出（`src/utils/anon.ts`），不落库。于是：

- **同一条帖子下**（帖子本身 + 你在这个帖子下发的评论）假名保持一致，读起来像个对话；
- **跨帖子则完全不同**。

后面这一点不是缺陷，是刻意的：它挡住了「靠昵称把一个人散落各处的发言串起来」
这种去匿名化手段。你自己不受影响 —— 你的内容旁边会有一个「我」的标记。

**约束规则**：`authorId` 全项目只允许在 `src/mock/mappers.ts` 里被读取。
组件想判断「是不是我发的」，只能用 `isMine` 这个布尔值。
这样匿名性是**结构性**成立的，而不是靠人记得「别在模板里写 authorId」。

副作用之一：因为对外拿不到作者 id，所以**做不出「查看别人的主页」**。
路由因此是 `/me` 而不是 `/u/:name` —— 如实反映数据模型的能力边界。

## Mock 是怎么工作的

| 问题 | 答案 |
| --- | --- |
| 数据存在哪？ | localStorage 的 `treehole:db:v1` 这一个 key 下（整个库一个 key，方便一次重置） |
| 图片存在哪？ | **另一处**：IndexedDB 的 `treehole:images` 库。原因见下一节 |
| 登录状态存在哪？ | localStorage 的 `treehole:session:v1` |
| 怎么重置？ | 页脚「关于」页里有重置按钮；也可以直接访问 `#/?reset=1`（两处存储都会清） |
| 请求延时？ | 模拟 120~400ms，可用 `VITE_MOCK_LATENCY_MS` 调整或关掉 |
| 会失败吗？ | 默认**不会**。想演示错误分支，执行 `localStorage['treehole:chaos'] = '0.3'` 再刷新 |

**改了数据结构怎么办？** 把 `src/mock/constants.ts` 里的 `SCHEMA_VERSION` 加一。
不这么做的话，浏览器里残留的旧结构数据会让某处读到 `undefined` 然后白屏 ——
而无痕模式打开却一切正常，这个反差很容易把人引向完全错误的排查方向。
版本不匹配时会自动重新播种。

**将来要接真实后端？** 只需要替换 `src/api/*` 里的实现，保持函数签名不变，
组件一行都不用改。这也是 `api/` 和 `mock/` 分成两层的原因。

## 编号、赞和踩

**编号**（`#7`）和帖子的内部 id 是两件事。id 是主键（`p_muwy8615...`，给数据库用的），
编号是给人看、给人搜的。它从 1 开始、只增不减，**删掉 #3 之后 #4 仍然是 #4** ——
编号不随删除重排，所以已经发出去的链接和截图里的编号不会突然指向别的帖子。

编号**随时间递增**：最早的帖子是 #1，越新的号越大。注意信息流是「最新在前」排的，
所以看起来编号是递减的（`#13 #12 #11…`）—— 这是对的，不是错乱。

> 种子数据这里踩过一次坑：`POST_SEEDS` 数组本身是按「最新在前」写的（这样读代码时
> 像在读信息流），如果顺手拿数组下标当编号，最新的帖子就会变成 #1、编号和时间完全
> 反着走，新发的帖子还会插在 #1 上面。所以 `seed.ts` 里编号是**反过来**取的。

编号由一个存在库里的**序列**（`Db.nextPostNo`）发放，所以删掉编号最大的那条帖子之后，
下一条新帖拿的是下一个号、而不是把空出来的号捡回来。

> 这里初版写成了「当前最大编号 + 1」，看起来更简单、还没有第二个状态。但它做不到
> 「永不复用」：删掉最新的 #13，再发一条又是 #13，同一个编号在几天内指向两条不同的
> 帖子。序列多出来的那一点状态买的正是这个性质。发号时还会和「现有最大编号 + 1」
> 取一次 max，万一序列落后于数据（旧版本残留、手改过 localStorage）也能自愈。

搜索时**编号和正文是并列的条件**，不是二选一：输入 `7` 既会命中 7 号帖子，
也会命中正文里写着「7」的帖子。这样最不容易让人意外 —— 想搜哪种，结果都在；
而且每条结果都带着编号，一眼就能认出哪条才是编号命中的那条。

**赞和踩互斥**：点其中一个会自动撤掉另一个。这和大多数平台（包括 B 站）一致，
也避免出现「同一个人既赞又踩」这种数据上说得通、界面上看着像 bug 的状态。
因此 `toggleLike` / `toggleDislike` 返回的是这条帖子**完整的**表态状态
（赞和踩各两个字段），而不是只返回被点的那一个 —— 否则客户端得自己猜另一半
变成了什么，那正是乐观更新最容易悄悄错的地方。

踩不是装饰性的：**「热门」排序的分数是 `赞 × 2 + 评论 − 踩`**，被踩的帖子会往下沉。

> 一个可以顺手改掉的小地方：目前每条卡片都会显示 `▽ 0`。如果你觉得零踩的帖子
> 也显示一个「0」有点吵，在 `ReactionBar.vue` 里给踩的 `.count` 加个
> `v-if="dislikeCount > 0"` 就行。

## 图片是怎么存的

配图**没有**跟帖子存在一起，而是单独放在 IndexedDB（`treehole:images`）里。
这不是随手做的选择，最主要的理由只有一条：

> localStorage 全站只有约 5 MB，而我们的整个数据库是**存在单个 key 下的原子写入**。
> 图片体积不可控，一旦把它撑爆，`saveDb()` 会抛 `QuotaExceededError` ——
> 用户的帖子、评论、点赞会**一起**存不进去。让图片有机会连累主库，是这个设计里
> 最不能接受的事。

另外两条是顺带的：localStorage 只能存字符串，图片转 base64 会平白多出 33% 体积；
而 IndexedDB 能直接存 Blob，配额也大两个数量级。

**存进去之前会先压缩**（`src/utils/image.ts`）：等比缩到最长边 1600px，再转成
WebP（quality 0.82）。一张 2400×1800 的图大约会变成 1600×1200 的几十 KB。
不会放大小图。选择上限是单张 20 MB、单次 4 张 —— 这两个数在
`src/utils/image.ts` 和 `src/components/common/ImagePicker.vue` 里。

几个容易漏掉、但都处理了的边界：

- **图存了、帖子没建成**：会调用 `discardImages()` 把刚写进去的图删掉，
  否则它们会变成永远没人引用、用户也看不见的垃圾（`NewPostView.vue`）；
- **删帖 / 删评论**：连同其下评论的图一起回收，不留孤儿 blob（`src/api/posts.ts`）；
- **object URL 必须显式 revoke**：否则对应的 blob 会一直钉在内存里，
  用户翻多少页就攒多少（`ImageGallery.vue`）；
- **图片丢了不白屏**：用户在别处清过浏览器数据时，`getImage()` 返回 `undefined`，
  界面退化成一句「配图已丢失」。

> **种子数据里没有图片** —— 因为图片是二进制，塞进 `seed.ts` 会又大又难看。
> 所以想看到这个功能，需要你自己发一条带图的帖子或评论。

## 关于可复现

- `package-lock.json` **已提交**，所以请用 `npm ci` 而不是 `npm install`。
  `npm ci` 严格按锁文件安装，装的是一模一样的依赖树；`npm install` 可能会在
  允许的版本范围内升到你没验证过的版本。
- `.nvmrc` 与 `package.json` 的 `engines` 都标了 Node 版本。
  刻意**没有**开启 `engine-strict` —— 让 Node 版本不满足的人撞上一串看不懂的
  npm 报错，比它要防的问题更麻烦。
- `.github/workflows/ci.yml` 每次推送都会跑 lint + 类型检查 + 构建。
- `.gitattributes` 固定了 `eol=lf`，避免 Windows 和 macOS 之间来回换行符。

## 关于安全性

**这是一个演示环境，不是可以直接上线的产品。** 具体地说：

- 没有任何服务端校验，所有「权限」都只是前端逻辑，改一下 localStorage 就能绕过；
- localStorage 里的内容，同一台机器上的任何人都能读能改；
- 密码只做了一层形式上的不可逆处理（`src/mock/password.ts`），
  那不是密码哈希，也挡不住任何人。

**请不要在这里使用你任何一处正在使用的真实密码。**

## 已知限制

- 评论是扁平的一层，没有楼中楼（数据模型里预留了 `parentId`，将来加回复不需要数据迁移）
- 不能查看别人的主页（原因见上文「匿名是怎么做的」）
- 个人主页只有「我的帖子」和「我赞过的」，没有「我踩过的」——
  踩过的帖子取消踩之后就找不回来了，只能靠编号或搜索
- 配图不能粘贴上传，也不能发外链，只能选本地文件；没有私信、没有通知
- 首屏 JS 体积较大（约 280 KB gzip），因为 Element Plus 是全量引入的。
  换成按需引入可以显著减小，但那会引入配置和 ESLint 之间的摩擦，
  在这个规模下不划算。
